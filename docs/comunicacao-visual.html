Resumo: o cliente só fala com o gateway (HTTP com resposta). Keycloak entra no token e na validação JWT nos serviços. Copiar dados do banco fake é HTTP entre microsserviços, após eventos Kafka.

publish → tópico consume (@KafkaListener) HTTP após consume Mongo / Redis

Como ler: siga A → B → C na horizontal. Cada consume dispara trabalho local + HTTP ao mock. Kafka coordena quando sincronizar; o conteúdo bancário vem sempre do mock-institution.

Tópicos DLQ criados no startup. Mensagens na DLQ mantêm headers do Spring Kafka (tópico original, exceção) para debug.
